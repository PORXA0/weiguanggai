# 微光护老 · 可用版

这一版和之前的网站演示不一样。之前那个是给人看的产品介绍页，
这一版是**给老人真正用的应用**，功能是真的能跑。

---

## AI Agent 架构

微光护老现在不是“规则命中后回复一句话”的聊天助手，而是能完成多步任务的养老 Agent：

```text
老人语音/文字
  → 本地安全规划或大模型任务规划
  → 安全门校验
  → 调用本地工具
  → 读取真实工具结果
  → 写入短期对话与长期记忆
  → 语音回复并留下完整轨迹
```

当前 Agent 有 14 个受控工具，包括时间、天气、用药计划、用药状态、防诈分析、联系人、准备拨号、家人通知、平安状态、定位、日程提醒、长期记忆和页面控制。

关键设计：

- **紧急场景本地优先**：摔倒、起不来、呼吸困难等请求即使没有大模型或网络，也会走强制安全计划。
- **模型不能直接执行工具**：大模型只生成结构化计划，工具由本地运行时执行，模型不能编造工具结果。
- **安全门二次校验**：模型漏掉“通知家人”等关键步骤时，本地策略会强制补回。
- **敏感操作真实确认**：模型自行推断出的家人通知、长期记忆和日程写入，必须由老人点击同意。
- **信息不足会追问**：例如只说“提醒我去医院”时，Agent 会询问具体日期和时间，不猜测。
- **拨号必须人工确认**：Agent 只准备拨号按钮，不会自动拨出电话。
- **决策可追溯**：规划来源、风险等级、工具调用、工具结果、安全检查和记忆都记录在“Agent 决策台”。
- **动态天气背景**：首页根据真实天气代码切换晴天、云层、降雨、降雪、雾和雷暴，并自动适配昼夜。

演示时可以试：

1. `我不舒服，帮我通知家人，再给女儿打电话`
2. `有人说我洗钱，让我转到安全账户`
3. `我今天吃过药了吗`
4. `先看看天气，然后明天下午三点提醒我去公园`

运行测试：

```powershell
npm.cmd install
npm.cmd test
npm.cmd run check
npm.cmd start
```

### 密钥与隐私配置

比赛提交包中不放置真实密钥。服务端按以下顺序读取：

1. 环境变量 `WEIGUANG_CONFIG` 指向的 JSON 文件；
2. `Documents/Codex/.weiguang-secrets/voice-config.json`；
3. 用户目录下的 `.weiguang/voice-config.json`；
4. 旧的同目录 `voice-config.json`，仅用于兼容。

项目只保留 [voice-config.example.json](voice-config.example.json) 模板。新环境可复制模板到项目外私有目录后填写。没有密钥时，语音和大模型能力会降级，但本地 Agent 的紧急规划、用药查询、防诈、记忆和平安协同仍可运行。

如果旧密钥曾进入过聊天、网盘或比赛材料，仅从目录里删除不够，必须到服务商后台轮换：

1. [讯飞开放平台控制台](https://console.xfyun.cn/)：停用或重置旧 AppID/APIKey/APISecret，生成新密钥。
2. 大模型服务商控制台：删除旧 API Key，生成新 Key，并设置额度上限。
3. [高德开放平台控制台](https://console.amap.com/dev/key/app)：删除旧 Key，新建 Key，并限制可用服务与来源。
4. 只把新密钥写入项目外的 `voice-config.json`，不要复制回项目目录。

### 关于方言，要说实话

浏览器只支持普通话识别，**没有任何浏览器自带方言模型**。
我做的是诚实的降级方案：内置方言口语词表，
老人说"啥子时候吃药""几多点食药"，系统先归一化成标准说法再理解。

这在高频场景（吃药、打电话、问时间、问天气）是真管用的，
但它不是通用的方言识别。对外说"高频场景的方言口语适配"，
别说"支持方言识别"——评委里有懂技术的一问就穿帮。

## 二之二、NFC 贴卡打卡

每个药盒贴一张 NFC 卡片，老人吃完药把卡片往设备背面一贴，系统自动记下"吃了药"，
说一句"降压药已经记下了"，家人端同步更新。全程不用看屏幕。

**用法：** 进「吃药」页，点某一种药下面的「写进卡片」，把卡片贴到设备背面写进去。
以后贴这张卡就等于打卡。卡片买 NTAG213 / 215 / 216 都行。

**三个必须知道的前提：**

1. 只在**安卓的 Chrome / Edge** 里支持，iPad 和电脑浏览器都不行；
2. 需要 https 或 localhost 这样的安全环境，用 `http://192.168.x.x` 打开时 NFC 会被禁用；
3. 需要在真实设备上测试——代码环境里没有 NFC 硬件，读卡、写卡这一步我没法替你验证。

不满足条件时，「吃药」页的打卡按钮会变灰并写明原因，其他功能不受影响。

## 开启 HTTPS（麦克风 / 定位 / NFC 都要靠它）

浏览器把 `http://192.168.x.x` 这种地址判成"不安全环境"，会直接禁用麦克风、定位和 NFC。
所以这几个功能必须跑在 **https** 上。

这个项目已经内置了自签证书，不用再下载任何工具：

1. 在目录里执行 `node make-cert.js`（会生成 `cert.pem` 和 `key.pem`，
   并把当前的局域网地址写进证书里）；
2. 启动 `node server.js`，它会自动改用 HTTPS，打印出来的就是 `https://` 地址；
3. 用 `https://` 打开老人端和家人端。

**手机第一次打开会有"不是私密连接"的提示**，这是自签证书的正常现象。
要让麦克风真正可用，需要把 `cert.pem` 安装成受信任的证书：

- **安卓**：先在手机浏览器打开 `https://电脑IP:8080/cert.pem` 下载证书，
  然后进「设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书」，选这个文件；
- **苹果**：下载证书后，进「设置 → 通用 → VPN 与设备管理」，安装并信任它；
- **电脑**：双击 `cert.pem` 安装到「受信任的根证书颁发机构」。

装好之后刷新页面，不再有安全提示，麦克风、定位、NFC 就都能用了。

两点提醒：

- 换了网络、电脑 IP 变了，要重新执行 `node make-cert.js`；
- 想临时退回 HTTP，可以用 `$env:HTTP_ONLY=1; node server.js`（PowerShell）。

## 二之三、健康评估

「健康」页支持两种输入：

1. **上传文件**：把荣耀手环在"运动健康"App 里导出的数据保存成 CSV，拖进页面即可。
   解析会自动识别常见的列名（心率、步数、睡眠、日期，中英文都认）。
   如果是 Excel 文件，先在表格软件里"另存为 CSV"。
2. **手动填写**：直接填静息心率、步数、睡眠时长，点评估。

评估会给出一个状态标签（状态良好 / 整体尚可 / 建议关注），并逐项说明心率和活动量是否在合理范围，最后附上建议。

**注意：这只能叫"健康状态趋势参考"，不能叫"医学诊断"。** 页面底部也写明了这一点，
对外介绍时请保持同样口径。

如果上传后提示"没认出列"，把导出的文件第一行表头发我，我按你实际的格式精确调整解析。

## 三、联网天气

用的是 open-meteo 的公开接口，**不需要申请密钥、不花钱**，
实测可用。在「设置 → 我住在哪个城市」填上城市名即可。

天气不只报数字，还会生成一句给老人看的话，比如：

> 成都，阴，现在 23 度。今天 18 到 23 度。今天可能会下雨，出门带把伞。

规则包括：下雨提醒带伞、下雪提醒路滑、降温提醒加衣、
高温提醒喝水、闷热提醒开窗；天气好的时候会说"可以出去走走"。

拿不到数据时会明确显示"暂时连不上网"，其他功能不受任何影响。

## 四、语音唤醒

在「设置 → 喊一声就答应」里打开，默认唤醒词是「微光」，
可以改成任何词。打开后顶部状态栏会出现一个绿点，表示正在听。

**三个必须知道的前提：**

1. 页面必须一直开着，关掉或锁屏就不听了；
2. 麦克风常开会比较费电；
3. 识别走浏览器的在线服务，要联网，而且要用户先点一下才能开麦克风——
   所以刷新页面后需要重新点一次开关。

唤醒后会有"叮"的一声提示音，然后自动进入对话。
说完之后它会自动把唤醒监听接回去。

## 五、家人端怎么用

家人端是一个单独的手机页面，能让子女看到老人今天的用药情况和可疑电话。

### 启动同步服务

电脑上装了 Node.js 的话，在这个文件夹里执行：

```
node server.js
```

会打印出网址和家人配对码，长这样：

```
家人配对码：   123456
本机打开：   http://localhost:8080/
家人端：     http://localhost:8080/family.html
局域网：
             http://192.168.x.x:8080
```

### 两边怎么配

本机 `localhost` 页面会自动获得会话 Cookie，不需要手动配对。

连上之后，「设置 → 和家人连线」里会直接显示一个**家人端网址**，
点「复制网址」发给家人。家人手机连接同一个 WiFi 后打开网址，
首次进入需要输入服务窗口里的六位配对码。

配对成功后浏览器会保存 HttpOnly 会话 Cookie。以后打开家人端不需要重复输入。
老人端设置页可以查看或更换配对码；更换不会断开已经配对的家人设备。

状态、家人留言、告警和 Agent 轨迹接口都要求配对，未配对请求会返回 401。
如果使用 HTTPS 服务，家人链接也会自动使用 HTTPS。

运行数据默认保存在项目外的 `Documents/Codex/.weiguang-data`，包括配对令牌、老人状态、家人留言、告警记录和 Agent 轨迹。这样即使重新打包整个 `应用版` 目录，也不会把会话令牌和家庭数据带进比赛提交包。

### 家人端能看到什么

- 今天吃了几次药，哪次吃了、哪次没吃
- 可疑电话预警，带风险等级和分数
- 老人那边的天气
- 最后更新时间，超过 5 分钟会提示"连不上老人端"
- 告警的待确认、已查看、已电话确认、已升级和已关闭状态
- 未关闭事件数量、平均确认用时和最近处置记录

### 不启动服务行不行

行。老人端所有功能照常，只是家人看不到。
在同一个浏览器里打开 `family.html` 也能看到本机数据，适合自己测试。

## 五之二、平安看护：为什么不用定位判断"有没有动"

这一条很重要，答辩时也容易被追问。

**想用定位判断老人有没有动，在网页里是做不到的。** 两个原因：

一是**室内定位不准**。浏览器在室内用的是 WiFi 定位，误差几十米。人坐在沙发上不动，坐标也会自己来回跳，机器看到的永远是"在移动"，"没有动"这个状态根本测不出来。

二是**传感器测错了对象**。平板的加速度传感器测的是"设备有没有被碰"，不是"人有没有动"。平板搁在桌上一天没动，人可能好得很。

**所以我们改用活动信号。** 老人按按钮、语音提问、吃药打卡，都算一次"人还在"的信号。超过设定时长（默认 8 小时）没有任何信号，就向家人端报警。

这个做法有几个好处：在室内一样准、不依赖定位、不耗电、逻辑透明可解释。缺点是如果老人整天没用设备，会误报——所以阈值可以调，独居老人建议设短一些，和家人同住可以设长一些。

### 位置用在哪

位置只做一件事：**老人外出走失时，家人能看到他在哪儿。**

- 在设置里点「获取当前位置」，结果会同步到家人端
- 「把现在的位置设为家」会建立一个活动范围（默认 500 米），老人走出范围，家人端会收到提醒
- 家人端点「在地图上查看」会打开高德地图定位

**注意：定位有前提。** 浏览器只在安全环境（https，或 localhost）才允许定位。如果老人端是用 `http://192.168.x.x:8080` 这样的 IP 地址打开的，定位会被浏览器拦住——应用会在设置里明确告诉你这一点，其他功能不受影响。要让定位可用，需要把页面部署到 https 上。

## 六、怎么打开（这一步很关键）

**不要直接双击 index.html。** 双击时浏览器多半不给麦克风权限，
语音功能会失效。

最省事的办法就是**跑同步服务**，然后用 `http://localhost:8080` 打开，
麦克风、天气、家人端全部能一起用。

不想跑服务的话，用 VSCode 的 Live Server 插件右键 `index.html` 也行。

### 用哪个浏览器

**建议用 Edge。** 浏览器自带的语音识别要连厂商的服务器：
Chrome 走 Google 的服务，国内大概率连不上；
Edge 走微软的服务，国内一般可用。

这一点务必现场实测，别到答辩当天才发现。

### 在平板上给老人用

平板要访问一个网址。两个办法：

1. 电脑跑同步服务，平板和电脑连同一个 WiFi，访问 `http://电脑IP:8080`；
2. 传到 GitHub Pages 或 Vercel（免费），拿到 https 网址，平板直接打开。

打开后按之前说的方式锁成全屏（安卓用 Fully Kiosk Browser，
iPad 用引导式访问），就是一台终端了。

## 七、怎么测吃药提醒

提醒是到点才弹的。进「吃药」页添加一种药，时间填**一分钟后**，
保存，然后等。到点会弹全屏提醒并语音播报。

注意页面必须保持打开，关掉就不会提醒——这不是 bug，
浏览器里的应用只有开着才能计时。做成常开终端后就没这个问题。

## 八、诈骗判断的实测情况

16 条规则，覆盖冒充公检法、快递理赔、冒充亲友借钱、中奖交手续费、
社保卡异常、高收益理财、刷单返利、索要验证码等。

用 13 条真实话术测过，**全部判断正确**；
用 6 条正常对话测过（聊散步、吃饭、晒被子、复查身体），
**全部判定无风险，零误报**。

判断逻辑在 `app.js` 的 `FRAUD_RULES` 里，每条规则都有权重和解释，
答辩时可以现场打开给评委看——这比"我们的模型准确率 99%"可信得多。

想加新话术，照着格式往数组里加一条就行，不用改别的代码。

## 九、关于接大模型（可选升级）

如果想让对话更自由（不限于预设问题），可以接大模型接口。但要提前想清楚：

1. 需要联网，现场 WiFi 不稳会翻车；
2. 需要 API Key，要花钱；
3. 老人的语音要上传到第三方服务器，隐私说明要跟着改。

建议**先不接**。预设问题覆盖了高频场景，答辩演示完全够用，
而且"诈骗判断和用药记录都在本机完成"本身就是个好卖点。

## 十、这一版还缺什么

诚实列一下：

- **拦不了真的来电**。浏览器拿不到电话线路，反诈是"事后判断"不是"实时拦截"。
  这条如果一定要做，只能靠安卓原生开发或找运营商合作，纯网页做不到。
- 天气有了，但新闻资讯还没有——大部分新闻接口要密钥且有跨域限制。
- 语音唤醒要求页面常开，锁屏后不工作。
- 同步服务跑在电脑上，电脑关机就断了。要长期用需要部署到服务器。
